# 本地模型连接器（local-rkllm）

把开发板上的 Qwen3.5-4B 推理服务接成可随时调用的连接器，用于日常的轻量文本粗加工（改写、摘要、分类、提取、翻译等）。

本连接器是 rkllm-runtime 项目的附属设施：它复用的正是本项目测试工具链里的板端客户端实现。

## 一、文件构成

| 文件 | 作用 |
| --- | --- |
| `server.py` | MCP 服务层：stdio 协议处理 + 4 个工具定义 |
| `rkllm_client.py` | 调用封装：多目标配置 + 预算防护 + 可选复用工具链 `Board` |
| `targets.conf` | 本机配置：一行一个本地部署（含令牌），不入资料库 |
| `targets.example.conf` | 配置模板（令牌已脱敏），随项目归档 |
| （本机）`~/.workbuddy/mcp.json` | MCP 注册，由客户端拉起服务 |

## 二、运行位置与归档位置

| 位置 | 路径 | 说明 |
| --- | --- | --- |
| 运行位置 | `~/.workbuddy/mcp-servers/local-rkllm/` | 本机被加载的地方，可置于任意目录（连接器自包含） |
| 归档位置 | 本资料库根目录 `本地模型连接器/` | 项目附属设施存档，本次归档 |

两处内容一致。修改时以运行位置为准，改动后同步回归档位置。

## 三、配置：目标与 MCP 注册

### 3.1 本地部署目标（`targets.conf`）

连接器不写死任何地址，支持的本地部署数量不限。配置是运行目录下的纯文本 `targets.conf`
（可从 `targets.example.conf` 复制一份）。

写配置前建议先读 `targets.example.conf`——已重写为全键参考版：含全部可配置键（含中文别名）、档位别名、各档生效值对照、数值校验规则与环境变量说明。

写法是一行一个目标，地址与密钥用 `@` 连成一个字段（无歧义）：

```text
# [名称 =] 地址[@密钥] [preset=档位] [其它 键=值] [备注…]
board = 192.0.2.10:8080@TOKEN                   # 地址与密钥用 @ 连成一个字段，无歧义
192.0.2.50:8080                                 # 无密钥直接写地址（addr@ 表示空密钥）
box-7b = 192.0.2.51:8080@TOKEN preset=7b        # 按参数量选档
box-auto = 192.0.2.60:8080@TOKEN preset=auto model=qwen2.5-14b-instruct
tunnel = https://xxx.goho.co@TOKEN preset=4b link=tunnel   # 穿透：https + 标链路
default = board                                 # 指定默认目标（不写则取第一个）
```

| 位置 | 必填 | 说明 |
| --- | --- | --- |
| 名称 | 否 | `名称 =` 或空格分隔都认；省略时用地址当名称。`default` 也可以作目标名：`default = 127.0.0.1:8080` 会被认成目标定义，只有值确实是已定义的目标名时才是「指定默认目标」 |
| 地址 | 是 | `ip:port`；也接受完整 URL，`http://` / `https://` 前缀都认并按前缀发起请求——仅 HTTPS 的地址（内网穿透、反代等）必须写 `https://`，不写前缀按 http 处理 |
| 密钥 | 否 | 用 `@` 绑在地址上（推荐，无歧义；兼容旧式独立密钥列与 `key=` 具名项）。仅支持 ASCII——非 ASCII 会被忽略并告警（HTTP 头无法承载）；省略按「无令牌」处理 |
| 备注 / `model=` | 否 | 地址（含 `@密钥`）之后的具名项与文字；模型用 `model=xxx` 具名指定（实际以服务端返回为准） |

对写配置友好：`#` 之后是注释、行首 `;` 也是注释、多余空格自动折叠，写错了会在 stderr 给出行号 + 原因。

#### 3.1.0 能力描述：`[ability]` 段

给调用方模型看的能力边界说明，写在 `[ability]` 段（段位置无关，推荐放文件末尾）：

```text
[ability]
board = 板端 4B（实测档）：短文本改写 / 摘要 / 分类 / 信息抽取；输出上限 768 token。
box-7b = 7B 档（GPU）：改写 / 摘要 / 抽取；输出上限 1536 token。
```

段内一行 `目标名 = 描述`，覆盖该目标的档位默认描述；未写的目标回落到档位默认。行内 `能力=` 旧式仍兼容，但推荐段式（行内形式其后所有文字都会被当作描述，易误吞备注）。注意段内描述避免使用 ` #`（会被当作行内注释截断）。

#### 3.1.1 档位 `preset=`（按参数量分档，一行切一组阈值）

| 档位 | 输入 | 输出 | 上下文 | 吞吐假设 | 超时下限 | 说明 |
| --- | --- | --- | --- | --- | --- | --- |
| `default` | 2600 | 768 | 4096 | 6.3 tok/s | 60s | RK3588 板端实测档（不写就取它） |
| `1b` | 3000 | 512 | 4096 | 8 tok/s | 60s | 短句纠错、关键词抽取 |
| `3b` | 5500 | 1024 | 8192 | 5 tok/s | 120s | 短改写、单段摘要 |
| `4b` | 6000 | 1024 | 8192 | 4 tok/s | 120s | 短改写 / 摘要 / 抽取 |
| `7b` | 6000 | 1536 | 8192 | 3 tok/s | 180s | 中等摘要、结构化抽取、短代码 |
| `14b` | 12000 | 2048 | 16384 | 2 tok/s | 240s | 较长摘要、多步问答、中等代码 |
| `32b` | 24000 | 3072 | 32768 | 1 tok/s | 300s | 接近通用能力（本地部署实用上限） |
| `auto` | — | — | — | — | — | 按 `model=` 里的参数量自动选最接近的档（`qwen2.5-14b` → `14b`） |

吞吐一列取的是**不会误杀的下界**（弱 NPU 上 1B 也可能只有 5 tok/s），只用于放宽超时：实机更快不会变慢。**换机器后先跑一次 `calibrate`**，把实测值写进配置。

档位表不含链路信息——链路是部署属性，不是模型属性，用 `link=` 单独标（见下）。

#### 3.1.2 链路 `link=`（按目标区分直连与穿透）

两种形态访问的是**同一个板端服务**，差异只在链路，所以要按目标配，不能全局一刀切：

| 行为 | `link=direct`（默认） | `link=tunnel` |
| --- | --- | --- |
| `targets` 探测 | 并发（4 路），墙钟 ≈ 单次超时 | **串行**，逐条打印进度 |
| 同时在飞的请求 | 仅受同目标锁约束 | 全链路最多 2 个（隧道有限） |
| 适用 | 内网直连、本机 localhost | 内网穿透、反向代理、跨公网 |

同一进程里可以同时配直连目标与穿透目标，互不牵连。**所有目标无论链路都会探测**——探不全就不知道哪台还能用，只是穿透目标一个个来。

#### 3.1.3 上下文协商（服务端说了算）

首次调用某目标时会读一次 `/health`，若返回 `context_len` 且**小于**配置里的 `context`，就按服务端值下调（同时收紧 `max_in`）并告警一次。只下调不上调：配大了就是 KV 越界 → 原生库段错误。

`health=none` 或非 rkllm 服务（不返回该字段）时跳过协商，仍按配置值。配置改动后（文件 mtime 变化）会重新协商一次。

单项覆盖（写在目标行里，`键=值`；档位之后仍可逐项覆盖）：

```
max_in=2600  max_out=768  context=4096  tok_per_sec=6.3  timeout_floor=60
retries=2    retry_wait=8 chars_per_token=1.6 overrun=1.56 degen_check=on
health=rkllm | none | <任意 HTTP 路径>      # 非 rkllm 服务端用 health=openai（探 /v1/models）
```

能力说明：`ability=` / `能力=`（写在行尾，其后所有文字都算），会原样出现在 `local_llm_targets`
的结果里，用于告诉调用方模型该目标能做什么、不能做什么；不写则按档位取内置说明。

#### 3.1.2 实机校准（上线后必做）

```bash
python rkllm_client.py calibrate [--target 名称] [--tokens 384]
```

真跑一次约 300 字的长生成，量出含 prefill 的端到端吞吐（保守下界），并打印建议行，例如板端实测：

```
实测 6.77 tok/s（212 token / 31.33s）  →  suggest: preset=default tok_per_sec=6.77 timeout_floor=166
```

为什么必须实机做：档位里的吞吐是估算值，模拟测试测不出真实硬件与服务的差异。
2026-10-16 用此法在板端测出 6.3–6.9 tok/s，低于旧报告的 8–9 tok/s（长文稳态），
据此把默认档的 `tok_per_sec` 从 8.5 下调为 6.3 —— 超时从 137s 放宽到 178s，避免了长输出被误判超时。

配置来源优先级：`RKLLM_CONFIG` 指定的文件 → 运行目录 `targets.conf` → `targets.json`（旧格式，
仍兼容，按扩展名识别）→ 环境变量单目标（`RKLLM_HOST` / `RKLLM_API_KEY` / `RKLLM_MODEL`；
单目标可用 `RKLLM_PRESET` 选档）。全都没有时，调用会直接报错并给出照着抄的配置片段。

令牌不入资料库：`targets.conf` 含明文令牌，只保留在本机；随项目归档的是脱敏模板 `targets.example.conf`。

### 3.2 MCP 注册

```json
{
"mcpServers": {
"local-rkllm": {
"command": "<python.exe 绝对路径>",
"args": ["<运行位置>/server.py"]
}
}
}
```

目标配置（地址 / 令牌 / 模型）不写在注册里，统一由 `targets.conf` 管理——日后增删模型不必改客户端配置。
HTTP 层由目录内的 `board_api.py` 提供（无需任何环境变量），详见第五节。

## 四、暴露的工具

| 工具 | 用途 |
| --- | --- |
| `local_llm_ask` | 单轮问答，返回纯文本 |
| `local_llm_batch` | 多段文本逐段串行处理（长文分段场景） |
| `local_llm_health` | 指定目标的健康状态：在线与忙碌情况、队列长度、运行时长、累计请求统计 |
| `local_llm_targets` | 列出全部已配置目标（档位、生效预算、模型、备注、能力边界）及其可用性，并标出默认目标 |
| `local_llm_reset` | 清空会话历史（连接器侧 session + 服务端 `/v1/reset`）。服务端已默认 stateless，一般无需调用 |

`ask` / `batch` / `health` / `reset` 均支持可选的 `target` 参数指定目标；不传则用配置里的 `default`。

`local_llm_ask` 另有可选的 `session` 参数：**仅当目标配了 `history_turns>0` 时生效**，同一 session
的多轮调用会带上之前的对话。历史是拼进 prompt 文本的（不是 messages 数组），因为旧服务端只读
最后一条 user 消息、前几轮会被丢弃——拼进文本对新旧服务端都成立。默认 `history_turns=0`
（每次调用独立），因为 MCP 场景下通常由上游大模型自己维护上下文。
多目标下不同目标可并行，同一目标内部串行（板端是独占资源）。

任务分配约束（写进工具描述，约束调用方模型）：`local_llm_ask` / `local_llm_batch` 的说明里要求
调用方先看 `local_llm_targets` 的档位与能力边界，不要把超出该目标能力的任务交给它——
例如让 1B/4B 档写长文、写代码、做多步推理，或要求超过其输出上限的长度。
`local_llm_targets` 的结果里每个目标都会带上一条能力说明（档位内置，可用 `能力=` 覆盖）。

## 五、依赖、独立性与移植

### 5.1 零外部依赖

纯标准库（`urllib` / `json` / `threading`），HTTP 层是同目录的 `board_api.py`，不依赖
任何其它项目目录、不依赖第三方包。
把 `local-rkllm/` 整个目录拷到任意能访问板端服务的机器上即可运行，Windows / Linux / macOS 均可。

### 5.2 HTTP 层：与工具链共用 board_api.py

`board_api.py` 是工具链与连接器**唯一**的 HTTP 实现（URL 与认证头构造、超时、
SSE 解析、健康判定、百分位）。改造前连接器自带 `_SimpleBoard`、工具链各脚本各写
一份，七份实现在"vLLM 的空 200 算不算活"这类判读上互相矛盾。

| 事项 | 现状 |
| --- | --- |
| HTTP 实现 | 同目录 `board_api.py`（与 `工具/大模型测试工具链/board_api.py` 内容相同） |
| 副本一致性 | `run_all.py` 预检比对两份；改一份必须同步另一份 |
| 旧机制 | `RKLLM_BOARD_SCRIPT` **已废弃**：不再 exec 工具链脚本取 `Board` 类，设了也不生效 |
连接器不因缺了主项目而失效——这是本附属应用与主项目解耦的关键。

走动态加载而非 `import`，是因为工具链脚本文件名以数字开头、不是合法 Python 标识符。
加载期间关闭字节码缓存写入，避免在主项目目录里留下 `__pycache__`。

> 

### 5.3 移植到另一台机器

1. 拷贝整个 `local-rkllm/` 目录到目标机器的任意位置

1. 在 `targets.conf` 里写一行「地址 + 密钥」（多台就多写几行）

1. 在目标机的 MCP 配置里注册：`command` 指向该机的 Python，`args` 指向 `server.py`

1. 不需要任何环境变量；`RKLLM_HOST` 等仅在不想用配置文件时才需要

不需要安装依赖，也不需要主项目在场。

### 5.4 本连接器负责的部分

主项目工具链没有、而日常调用需要的：预算防护（输入预检 / 输出封顶 / 客户端硬截断 / 退化特征自检）。

## 六、参数口径与依据

阈值全部取自本项目既有测试报告（`模型测试报告/Qwen3.5-4B性能测试报告` 与 `Qwen3.5-4B真实公文场景测试报告`），未单独实测：

| 阈值 | 取值 | 报告中的依据 |
| --- | --- | --- |
| 上下文硬上限 | 4096 token | 整篇润色时输入+输出 ≈4122 token 已溢出 |
| 输入预算 | 2600 token | 长 prompt（1000–2000 字）是崩溃高发区 |
| 输出封顶 | 768 token | 输出越过约 1000 token 时生成退化（重复字符流 + 串入无关英文模板） |
| 超时推算 | 60s 起，按 6.3 tok/s 计 | 2026-10-16 实机校准 6.3–6.9 tok/s（旧报告 8–9 tok/s 为长文稳态，端到端更慢） |
| 客户端硬截断 | 输出上限 ×1.56 | `max_tokens` 不被严格遵守，实际输出可能超出请求 |
| 串行约束 | 单进程内串行 | 并发无吞吐增益，QPS 恒 0.86–0.94（NPU 单请求串行） |
| 失败重试 | 2 次，间隔 8s | 长 prompt 偶发崩溃，由守护进程自动拉起 |
| 枚举类任务 | 会提前收尾 | 实测「数到 500」只输出到 23，别指望它做长枚举 |

以上为 `default` 档（RK3588 板端）的口径；其它尺寸档（1b…32b）是跨平台保守估算，
吞吐值故意取小，只用于把超时上限放宽（实际更快不会变慢）。换机器 / 换模型后请先跑
实机校准（见 3.1.1），再把建议值写回配置。

**运行期自适应**：每次成功调用都会记录 `completion_tokens / elapsed`。连续 3 次以上
（且每次输出 ≥40 token）算出的中位吞吐若**低于配置值的一半**，后续超时改按实测值推算，
并在 stderr 告警一次。只下调不上调——超时变小会误杀长尾请求。配置里的 `tok_per_sec`
写准了就不会有这条告警；收到告警说明该把它改成实测值（或跑一次 `calibrate`）。

**代理环境变量**：`urllib` 默认读 `http_proxy` / `https_proxy` / `all_proxy`。机器上配了
全局代理时，访问内网地址或穿透域名会被代理拦走，表现为「目标不可达」但浏览器能打开。
把板端地址或穿透域名加进 `no_proxy` 即可：

```bash
export no_proxy="127.0.0.1,localhost,192.168.0.0/16,xxxxx.goho.co"   # Windows: set no_proxy=...
```

改完重连连接器。穿透目标建议同时标 `link=tunnel`（见 3.1.2），让探测与并发按隧道能力收敛。

## 七、启用方式

不需要在界面上手动「添加」——`~/.workbuddy/mcp.json` 里的条目会直接出现在连接器管理页右上角的「自定义连接器」列表中，找到 `local-rkllm` 点「信任」即可。

| 情况 | 处理 |
| --- | --- |
| 列表里已有 `local-rkllm` | 直接点「信任」 |
| 列表里没有 | 重启客户端——`mcp.json` 在客户端启动时读取，写入晚于启动则本次不会加载 |
| 仍要手动添加 | 按下方字段对照填写（正常情况下用不到） |

### 手动添加时的字段对照

| 表单字段 | 填写值 |
| --- | --- |
| 名称 | `local-rkllm` |
| 类型 / 传输方式 | 本地命令（stdio） |
| 命令 | `<本机 python.exe 的绝对路径>` |
| 参数 | `<local-rkllm 目录>/server.py`（该目录可放在任意位置） |

目标（地址 / 令牌 / 模型）不写在注册里，改由运行目录下的 `targets.conf` 配置，见第 3.1 节。

保存按钮置灰的常见原因：必填字段（名称 / 命令）为空、名称与已有条目重复、或参数格式校验未通过。按下表填齐各项即可解除。

## 八、适用与不适用

适合：短文本改写、摘要（输出 \<300 字）、分类、信息提取、格式转换、批量文本粗加工（串行）。
不适合：长文生成、代码生成、需要精确控制输出长度的场景、高并发批处理、多轮迭代式精修（实测第二轮输出与输入 100% 重合）。

单次调用耗时 3～150 秒（取决于输出长度），调用方需容忍长等待。
