# 编译工具链 — rkllm-runtime Debian 打包

把 Rockchip RKLLM SDK（`rknn-llm-release-v1.3.1.tar.gz`，616 MB）裁打成规范、可安装、装完即用的 deb 包，目标平台 OrangePi 5 Plus 8G（RK3588，aarch64）。

本说明面向脚本使用者（每个脚本做什么、怎么跑、彼此怎么依赖）；工程的整体目标、产物清单与板端安装使用，见根目录 `文档/部署说明`。

---

## 一、脚本清单

  - `--profile full`（默认，目标板唯一构建）／`--profile slim`（剔除自带 OpenCV，改依赖系统 `libopencv-dev`）

  - 常用参数：`--arch`、`--package`、`--revision`、`--maintainer`、`--source`、`--out`、`--tree-dir`

  - 设 `SOURCE_DATE_EPOCH` 可改变打包时间戳（用于可复现构建）

  - ⚠️ `--emit-tree` 在 staging 目录已存在时会报错而不是自行删除（本机安全策略拦截 Python 进程内的删除操作），需先 `rm -rf build/tree-arm64`，或改用 `--tree-dir` 指定新位置

- `make_deb.py` — 构建器（主入口）
不依赖 `dpkg-deb`，直接产出 ar + tar.xz，因此在无 dpkg 环境的开发机上也能构建。

- `verify_deb.py` — 静态自检（88 项，本机无 lintian 时的替代）
覆盖：ar 容器、control 字段、md5 完整性、root 属主、权限位、目录覆盖、依赖格式、维护脚本副作用、`install()` 逃逸、CLI 渲染 / 语法 / 依赖、systemd 单元与转义、中英文 man page 结构、时间戳一致性、卸载残留面，以及 conffile 面（`conffiles` 声明、配置双语且不含版本号、每个参数都有配置项、`postrm` 在 remove 时也删除它）。
当前状态：FAIL=0 / WARN=0。省略参数时自动发现 `dist/` 下的包。

- `crosscheck_deb.py` — 与上游源 tarball 逐文件 MD5 比对，并打印安装后的权限与元数据。
用途：证明包内文件确实来自官方 SDK、未被意外改动。`used_upstream_entries.txt` 是裁剪依据留痕。

- `golden_diff.py` — 新旧栈输出差分对照：`--save` 录基线、`--compare` 对比，
  无参数用 `输入/rkllm-runtime-1.3.1/tests/golden_baseline.json`。本机 FakeEngine 级先行，板端只跑录/比。

- `render_caps_doc.py` — 由 `caps.py` 渲染 OpenAI 支持矩阵到 `文档/对话接口用法.md`（§8），`--check` 校验一致性。

- `render_template.py` — 单独渲染 packaging 模板（开发 / 调试 CLI 时用，不参与正式构建）。

## 二、典型用法

```bash
# ① 构建（目标板唯一构建）
python make_deb.py --arch arm64 --emit-tree
# ② 静态自检（省略参数则自动发现 dist/ 下的包）
python verify_deb.py
# ③ 与上游 tarball 逐文件比对
python crosscheck_deb.py
# ④ 板端自检（无模型也能跑，共 12 项；开发机无 NPU 时库/模型两项预期 FAIL）
rkllm selftest
```

前三条在开发机执行；第 ④ 条在板端执行。板端端到端验收（对运行中的服务实测，10 项：长 system 请求、空回合探测、模板污染、超长输入、崩溃存活等）原由 `verify_board.py` 承担，该脚本已归档，能力并入 `工具/大模型测试工具链/health_check.py --full`。

## 三、产物

| 产物 | 大小 | 说明 |
| --- | --- | --- |
| `rkllm-runtime_<version>_arm64.deb` | 14.00 MB（解包 84.2 MB） | 板端安装包：`/usr/bin/rkllm`、`librkllmrt.so`、C/C++ 示例、中英双语 man 手册；版本由源码 `DEFAULT_VERSION` 决定 |
| `rkllm-toolkit/packages/*.whl` | — | x86 主机用的模型转换工具，不进 deb |

模型不在包里：`.rkllm` 需在 x86 主机上用 `rkllm-toolkit/` 转换，流程见 `文档/对话接口用法`。

## 四、脚本依赖关系（改名会断链）

这三个脚本之间存在模块名耦合：

| 依赖 | 出处 |
| --- | --- |
| `import make_deb` | `render_template.py` 复用构建器的模板渲染逻辑 |
| `from tools.verify_deb import parse_ar, read_tar_xz` | `crosscheck_deb.py` 复用自检脚本的 ar 解析 |

因此这几个脚本不能加数字前缀、也不能改中文名——两者都不是合法 Python 标识符，改动会直接 `SyntaxError` / `ImportError`。这也是本工具链与本项目「脚本加序号前缀 + 英文名」约定的例外，属技术硬约束。

## 五、装完即用

```bash
sudo apt install ./rkllm-runtime_<version>_arm64.deb
rkllm selftest                 # 无模型也能验证安装（12 项，无 NPU 时库/模型预期 FAIL）
rkllm chat qwen2.5-1.5b        # 本地对话
rkllm serve qwen2.5-1.5b       # OpenAI 兼容 API（或 systemctl enable --now rkllm-server）
```

关键设计：`/usr/bin/rkllm` 是纯标准库 Python 脚本，通过 ctypes 直接调用 `librkllmrt.so`——板上无需编译，无需 pip。

卸载：`sudo apt remove rkllm-runtime`，控制文件与配置清理干净、无残留。
