# rkllm 板端服务改造计划（2026.10.21）

> 依据：资料库「总体设计」文档包（README / 总体设计方案 v1.0 / 审核报告 / 改造设计 v2 / MCP 接入与配置设计 v3）。
> 审核基线：仓库 HEAD `a0c149f`（1.3.1-15），与文档一致，可直接开工。
> 本文档是改造的执行总纲；每批改动完成后在此勾选并同步开发记录。

## 一、改造目标（合并三份文档的结论）

把板上 4B/7B 模型做成 WorkBuddy 可通过 MCP 调用的辅助工具：

1. **板端**：`rkllm serve` 从 3 122 行单文件重构为模块树（FastAPI + 推理子进程 + UDS 帧协议），修复审核报告 D1–D15；
2. **客户端**：自写纯 stdlib MCP 连接器 `rkllm-mcp`（stdio、6 工具、job 轮询、取消传导），以 wheel 交付；
3. **配置**：80 键 TOML 单一配置表，全部有默认值、启动校验、来源可查；
4. **诚实兼容**：能力三档（native/emulated/unsupported）单一事实源 `caps.py`，杜绝静默忽略。

三个硬约束：客户端 60 s 工具超时（>45 s 一律 job 化）；单 NPU 串行（有界队列+背压+取消）；8 GB 内存（4B/4096、7B/2048、27B 拒绝启动）。

实现中修正的三处自身缺陷（均有测试守住）：
1. worker 初版用两个 `makefile("rb")` 读同一 socket——run 与 abort 帧归属不可预期；
   重写为单读线程分发模型；
2. 连接 EOF 误触发进程级 `_shutdown` 导致 worker 处理完第一个连接即退出；拆出
   连接级 `_conn_closed` 与进程级 `_shutdown` 两个事件；
3. FakeEngine 逐字符流下测试只记最后一个 token——改为累积并断言 turn 递增。

剩余：第三批 S2（FastAPI + 队列 + SSE + supervisor + golden 差分）、第四批 S3
（agent/tools 解析、jsonmode、reasoning、conversation 回填）、第五批 S6（deb/wheel
打包 + WorkBuddy 实测）。S0 四个 spike 仍需板端实机。
