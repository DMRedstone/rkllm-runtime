## 一、审计结论（框架合理性）

**结论：框架整体合理，针对「单板 NPU + 资源受限 + Python 服务端」做了正确取舍，已在以下同层设计上达到或优于参照：**
- 子进程崩溃隔离（`Supervisor` 拉起 worker 子进程，kill -9 后 HTTP 存活、在飞请求 503、指数退避自愈）；
- 依赖契约解耦（`agent/gateway.py` 的 `InferenceGateway` Protocol 把 8 处属性耦合收敛为最小接口）；

- 前缀缓存（字节级 LCP + 相似度阈值，已用 `cache_hint` 规避 185MB 单轮 I/O 浪费）；

- [x] 🔴 **流式被心跳节拍限速到 15s/token**：`streaming.iterate_stream` 用
      `asyncio.wait({getter, watcher}, timeout=heartbeat_s)` 同时等「取 token」与「断连」——
      实测（Python 3.13 + uvicorn 0.54）集合里只要还有一个长期挂起的 task，另一个 task 的完成

      selftest 形同卡死）。

      `watch()` 另加 0.05s 退避，防 `receive()` 在某些 server/版本下空转饿死循环。
