extract 工具 100% 不可用
现象：调用 local_llm_extract（schema 无论多宽松，包括 {"type":"object"}）都报
MCP error -32600: Tool local_llm_extract has an output schema but did not return structured content。

根因（已沿代码链路坐实）​：

extract 声明了 output_schema（tools.py:102），所以 WorkBuddy 客户端强制校验顶层 structuredContent。
extract 实际永远走 job 路径——_default_estimate 对 extract 用 default_max_tokens*2（stdio.py:229-232），预估必然超 45s → 转 job。
job 完成后，_job_tool 的 get 分支（stdio.py:323-327）把 job.result（含 structuredContent/isError）整体 JSON 序列化后塞进 content[0].text 纯文本，顶层只返回 {content:[...]}，没有把 structuredContent/isError 提到顶层。客户端于是判定「声明了 output_schema 却无 structuredContent」→ 抛 -32600。
排除项：协议层 result_payload（protocol.py:59-70）和同步路径（stdio.py:217）都正确带结构化字段，只有「job 路径的工具」会丢结构化/错误标记。而 6 个工具里只有 extract 声明了 output_schema，所以唯独它中招；其余工具经 job 路径只丢 content 外字段，因无 output_schema 声明反而不报错。
