### 5.1 代码类

- [ ] **P0｜`mcp.tools` 配置全路径失效（连接器）**
  `__main__.py default_cfg` 的 `"tools": ()` 是 tuple，`_coerce_cfg_types` 不命中
  list 分支、走 else 被 str 化为 `"()"`；TOML 数组（→ `"['ask', 'chat']"`）与 env
  字符串（→ `"ask,chat"`）同样坏。`stdio._tool_enabled` 的 `set(enabled)` 把字符串
  按单字符打散 → ask/chat/extract/batch 全部误判「已禁用」（默认配置即触发，
  已实测复现）。当前 MCP 进程仍加载旧 `.pyc` 未爆发，**重启连接器即触发**；
  pytest 428 全绿没抓到是因为测试直接构造 cfg、不走 `load_cfg`。
  修复思路：① `default_cfg` 的 `"tools"` 改 `[]`（对齐板端 SCHEMA 的 list 模板）；
  ② `_tool_enabled` 兼容 str（逗号分割）与 list；③ 补一条走 `load_cfg` 的回归测试。
- [ ] **P1｜getresponse 阶段失败异常未归一、连接未清理（连接器）**
  `backend.py _request`：P2-D 收窄重试后，`conn.getresponse()` 抛 OSError/HTTPException
  时既非 `BackendError`（stdio 折成误导性 -32603 "internal error"）也未
  `_drop_connection`（半开连接残留线程本地，该线程连续两次失败才自愈）。
  修复思路：getresponse 包 try，失败时 drop 连接并抛 `BackendError("板端连接中断：…")`；
  **不重试**，保持非幂等语义。
- [ ] **P2（连接器，8 项）**
  - connect/read 超时不分离（`backend.py _connection`）：job 的 4200s 读超时连接被
    同步调用复用后，TCP 连接/无数据阶段最长挂 4200s（既有行为非回归）。
    思路：连接建立用独立短超时（~10s），建好后仅读阶段用大超时。
  - job 路径 busy 丢 retryAfter（`stdio.py _run_as_job` runner）：503 busy 只
    `job.fail("模型忙…")`，轮询拿不到可重试提示。思路：fail 文本附 retryAfter 建议。
  - JSON `Infinity` → OverflowError（`stdio.py` 3 处 `int(explicit)`）：-32603 而非
    -32602。思路：int 转换补 OverflowError 分支，或 `json.loads(parse_constant=…)` 入口拒绝。
  - `found.endswith("b")` 非 str 崩快照轮（`stdio.py:136`、`tools.py` status handler）：
    AttributeError 被吞、整轮 perf/limits 快照丢失。思路：加 `isinstance(found, str)`。
  - session_locks 只增不减（`tools.py:281-288`）：会话逐出后 per-session 锁残留。
    思路：`_purge_expired_locked` 时同步清锁表。
  - `max_concurrent=0` → 4 线程（`stdio.py:89`）：`or POOL_WORKERS` 把合法 0 当 falsy，
    与「默认 1 板端串行」相悖。思路：显式判 None。
  - TOML 解析失败静默（`__main__.py:105`）：mcp.toml 语法错误被吞、配置不生效无提示。
    思路：stderr 打一行警告（stdio 下 stderr 不进协议线）。
  - 首次 /health 刷新阻塞启动（`stdio.py:106`）：构造期同步调 status()（最多 10s），
    板端不可达时延迟 initialize。思路：首刷交给后台刷新线程异步完成。
- [ ] **观察项（4 项，不修复也能跑，登记备查）**
  - 板端 `queue.metrics` 的 `+=` 非原子：并发请求丢计数（`/metrics` Prometheus 为正本）。
  - `ops.py _hist_mean` 依赖 prometheus_client 私有属性 `_count/_sum`：库升级风险（有 try 兜底）。
  - `pipeline_runner.StreamTimer` 的 tuple 分支为死代码（`pipe.last_perf()` 恒 dict）。
  - `sse_stream.py` 错误路径不计 TTFT/时长指标。
