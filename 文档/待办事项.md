## 一、审计结论（框架合理性）

**结论：框架整体合理，针对「单板 NPU + 资源受限 + Python 服务端」做了正确取舍，已在以下同层设计上达到或优于参照：**
- 子进程崩溃隔离（`Supervisor` 拉起 worker 子进程，kill -9 后 HTTP 存活、在飞请求 503、指数退避自愈）；
- 依赖契约解耦（`agent/gateway.py` 的 `InferenceGateway` Protocol 把 8 处属性耦合收敛为最小接口）；
- 路由收敛（`pipeline_runner.py` 消除跨层私有导入）；
- 流式取消正确性（`CancelToken` 两段式，毫秒级生效，背压满投 `TRUNCATED` 而非伪造成功）；
- 前缀缓存（字节级 LCP + 相似度阈值，已用 `cache_hint` 规避 185MB 单轮 I/O 浪费）；
- OpenAI 兼容完整度（`/v1` + 根别名 + 显式 501，优于 lmstudio 静默忽略）。

## 三、性能整改（按严重度）

- [ ] 🔴 **P-背压去轮询**：`streaming.py` `_offer()` 队列满时 `time.sleep(0.01)` 轮询至 `PUT_TIMEOUT_S=5s`
      （跨线程无法 `await` 所致）。改线程安全 `queue.Queue(maxsize=…)` 桥接 + `put(timeout=…)` 阻塞替代轮询，
      或满即直接截断（截断语义已预期，无需等超时）；可去掉 `BACKPRESSURE_POLL_S` 轮询。
- [ ] 🟠 **P-worker 心跳 / 卡死自愈**：`supervisor.py:263 _start_health` 仅 `proc.poll()` 探活，
      NPU 推理死锁只能等 `request_timeout_s`（默认 900s）。worker 增周期心跳帧（如 `OP_HEARTBEAT`），
      `Supervisor` 检测心跳丢失即判卡死、主动重启，把发现卡死从 900s 降到秒级
      （版本校验 `ready.v` 已做，心跳可复用同一帧通道）。
- [ ] 🟠 **P-推理线程常驻**：`worker/engine.py:291 _stream_once()` 每次 `threading.Thread(...).start()`。
      引擎本就串行，改常驻单推理线程 + 任务队列，消除反复创建/销毁。
- [ ] 🟡 **P-minor-json 扫描**：`pipeline_runner.py:46 json_payload()` 用 `find("{")`/`rfind("}")` 全文扫描。
      流式收集时记录首尾花括号索引，省去全文扫描（影响有限，低优先）。
- [ ] 🟡 **P-minor-缓存 I/O**：`engine.py` 缓存文件约 185MB/次，已用 `cache_hint` 规避单轮浪费；
      多轮频繁写仍占 I/O 与存储磨损，可评估增量/压缩缓存。
